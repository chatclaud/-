Важно: поля health вида `hasGroq`, `hasMistral`, `hasTavily` и `hasNova` в основном отражают наличие конфигурации/переменной окружения, а не успешную авторизацию у поставщика. ## Этап B — `index.html`, JavaScript, `server.js`, `manifest.json`, структура архива

### Найденные дефекты исходного кандидата

1. **Критическая ошибка HTML:** начальный `<style>` открывался в строке около 36 и не закрывался перед загрузочным JavaScript. Первый `</style>` встречался лишь около строки 6817. В результате загрузочный код `window.__ccBoot`, закрытие `head`, открытие `body` и `appSkeleton` попадали внутрь текстового содержимого CSS вместо корректных HTML-элементов. Это могло нарушить инициализацию/диагностику интерфейса. В исправленном кандидате тег закрывается сразу после основного начального CSS; проверка парсером теперь находит `body`, `appSkeleton` и загрузочные скрипты отдельно.

2. **Абсолютные URL для GitHub Pages в подпапке:** `/sw.js` и `/icon-512.png` в проекте, опубликованном по пути `/-/`, указывали на корень домена, а не на папку проекта. Исправлено на `./sw.js` и `./icon-512.png`.

3. **Размер иконки в манифесте:** `apple-touch-icon.png` был файлом 512×512, но объявлялся как 180×180. Файл ресайзнут до 180×180; остальные иконки совпадают с размерами в `manifest.json`.

4. **Ложная инструкция деплоя:** `DEPLOY-README.txt` предписывал `npm run check:deploy`, но такого скрипта не было. В кандидате добавлены команда и `scripts/check-deploy.js`, проверяющие необходимые файлы, JSON манифеста, размеры иконок и критические пути.

5. **Частичный фрагмент API-ключа в логах:** `server.js` записывал последние четыре символа ключа Mistral при ошибке. Это удалено; значение ключа не нужно помещать в лог.

6. **Старый адрес API в localStorage:** ранняя инициализация могла использовать произвольный `CC_API_BASE`. В кандидате неканонический сохранённый адрес удаляется, и используется `https://chatclaud.onrender.com`. Это снижает риск отправки запросов на случайный/устаревший backend.

7. **Тайм-ауты провайдеров:** в диагностическом кандидате одна попытка Groq с тайм-аутом 55 секунд совпадала с клиентским тайм-аутом; затем запасная модель могла не успеть. В исправленном кандидате каждая попытка ограничена 8 секундами, максимум две попытки на провайдера, с сохранением перехода Groq → Mistral. Это улучшает контролируемое восстановление, но не гарантирует работу реальных внешних провайдеров.

## Что ещё нужно подтвердить на реальном сайте

Самая важная оставшаяся проверка — после публикации кандидата убедиться, что именно этот `index.html` обслуживается GitHub Pages и именно этот `server.js` запущен на правильном Render Web Service с папкой `modules/` в корне.

После деплоя: открыть `https://chatclaud.onrender.com/api/health`, отправить на сайте сообщение `Привет` и проверить логи Render. При нормальном прохождении должен появиться `[chat] start id=...`, затем `[chat] success ...`; при проблеме — `no_provider` или `fatal` с диагностикой. Только успешный ответ от реального провайдера подтвердит живую работу AI.
